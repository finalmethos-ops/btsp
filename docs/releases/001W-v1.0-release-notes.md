# BTSP v1.0 Release Notes

## Delivered

- Versioned BPP and Independent purchasing workflows with approval policies and notifications.
- Purchase requests, internal catalog lines, validations, drafts, and attachments.
- Purchase order generation, vendor splitting, artifacts, and transmission lifecycle.
- Vendor acknowledgements, shipment/ASN records, imports, connector scheduling, and operations.
- Receiving, variance, backorder, invoice matching, and reconciliation workflows.
- Operational analytics, exports, vendor scorecards, and scheduled reports.
- Governed user, role, configuration, workflow, notification, health, and audit administration.
- Least-privilege permissions, immutable event evidence, production configuration guards, and operational runbooks.
- Guarded live-presentation ordering load-test tooling with a production-host safety lock and
  documented isolated-event procedure.
- Frontend release images use an immutable Node base-image digest for reproducible builds.
- Responsive navigation controls use compact, accessible home and sign-out icons on small
  screens, and event inventory/model controls now constrain their children to the panel width.
- Native date and datetime controls now honor their grid cell width in event administration forms.
- Order submission failures are displayed inline immediately above the relevant submit button in
  both live-event and vendor buy-fair ordering flows.
- Operational workload cards use a dark, high-contrast severity palette so warning and critical
  metrics remain readable within the glass-themed administration UI.
- System-health operational metrics now exclude persistent in-app notification feed entries from
  transport backlog counts and ignore staff tasks belonging to events that have already ended.
  Reminder automation uses the same active-event boundary, preventing historical events from
  generating new overdue reminders.
- My Events command-center panels now use the same dark, high-contrast severity palette as System
  Health, including readable warning/critical action cards and controls.
- Vendor-hall floor-plan review notices now use the same dark warning palette with high-contrast
  analysis and matched-booth details.
- Event order review now uses dark, high-contrast status and feedback cards, with fixed column
  sizing and responsive horizontal overflow to prevent order totals, dates, and decisions from colliding.
- Event settlement reconciliation exceptions now use dark warning cards with high-contrast titles,
  descriptions, and reference identifiers instead of low-contrast pale panels.
- Event workspace success, error, and warning feedback now follows a shared dark semantic palette,
  while leaving compact state badges and inventory chips unchanged.
- Staff-task administration filters now use a dark container-responsive layout that wraps within
  split-screen and mobile panels instead of creating a white, horizontally clipped toolbar.
- Vendor Hall directory search, route planning, list view, and zoom controls now use contained dark
  workspace surfaces; the light floor-plan canvas is retained for booth-boundary readability.
- Marking a saved booth visited removes it from the suggested route, recalculates the remaining
  sequence from the mapped entrance, and highlights the completed booth in green on the map.
- Suggested-route booths and their numbered markers now occupy elevated map layers so stop numbers
  remain visible above the imported plan, grid, booth fills, and adjacent booth boundaries.
- Remaining Vendor Hall operational chrome—including booth popups, the loadout legend, meeting
  requests, and unmapped-booth fallbacks—now uses contained dark surfaces. Booth accessibility
  labels also announce route-stop numbers and visited state.
- Nginx and FastAPI now share an end-to-end `X-Request-ID`, emit structured request logs without
  query strings or payloads, and expose correlation IDs to approved browser clients for support.
- Production containers now use bounded compressed log rotation, and a recurring host watchdog
  records public health, container health/restarts, capacity, backup freshness, and gateway 5xx
  findings in a protected rotating JSON ledger with optional state-change webhooks.
- Authentication outcomes now create request-correlated `user.login` evidence, while user and
  role administration emit canonical `administrative.action` and `permission.changed` records.
  Failed attempts store hashes instead of raw submitted email or client-address values and never
  retain passwords, tokens, or request payloads.
- Approval policy evaluation now preserves disabled and no-match outcomes alongside positive
  matches, completing the evidence trail for fallback and fail-safe routing decisions.
- Production readiness now includes a non-disclosing secret audit covering defaults, strength,
  reuse, database consistency, runtime protected files, Git exclusion, network configuration,
  rotation metadata, and the required Windows ACL review boundary.
- Production readiness now rejects unpinned service images, missing or unexpected Compose
  services, stale running containers, and any runtime image whose content digest differs from the
  immutable digest configured for the deployment.
- Scheduled backups now use a live two-pass durable-file snapshot around PostgreSQL's consistent
  dump instead of stopping Nginx and the backend, eliminating the risk that an interrupted host
  task leaves the public application offline.
- Backend and frontend release images now use digest-pinned base images and standardized OCI
  source/version/build labels. A guarded clean-tree builder verifies those labels and records the
  local content IDs without automatically publishing or deploying anything.

## Database

The current BTSP baseline spans Alembic revisions `0001_initial_schema` through
`0116_notification_action_href`. Upgrade from an earlier deployment with
`alembic upgrade head`. Rehearse restore-based rollback against a
production-like backup before deployment; schema downgrades can discard data
introduced by later packages.

## Compatibility and boundaries

- PostgreSQL and Redis are required production dependencies.
- Durable attachment, purchase-order export, analytics-report, and invoice-intake storage must
  be backed up with the database.
- BTSP records payment approval but does not transmit funds or replace an ERP/general ledger.
- Vendor transports require deployment-specific workers, secret resolution, and partner certification.
- Human release, security, operations, and business approvals remain external governance gates.
